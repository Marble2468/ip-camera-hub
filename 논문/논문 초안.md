초록
최근 가정용 IP 카메라와 월패드 등 IoT 영상 장비의 해킹으로 인해 개인의 사생활 영상이 외부로 유출되는 사례가 지속적으로 발생하고 있다. 특히 저가형 IP 카메라의 경우 제조 단계의 보안 취약점, 백도어 가능성, 미흡한 펌웨어 업데이트 지원 등으로 인해 사용자의 비밀번호 관리만으로는 영상 유출 위험을 완전히 차단하기 어렵다. 본 연구는 IP 카메라가 외부 클라우드 서버와 직접 통신하는 구조를 개선하고, 라즈베리파이 기반의 보안 게이트웨이를 통해 영상 스트림을 로컬 환경에서 제어하는 시스템을 구현하는 것을 목적으로 한다. 또한 비인가 접속 상황에서 원본 영상이 노출되지 않도록 객체 탐지 기반 마스킹 처리를 수행하고, 마스킹 처리율과 누출률을 통해 성능을 평가한다. 본 연구를 통해 기기 제조사나 외부 클라우드 보안성에 의존하지 않고, 사용자 측 로컬 게이트웨이에서 영상 접근과 비식별화를 제어할 수 있는 IP 카메라 보안 구조를 제안한다.
주요어: IP 카메라, IoT 보안, 보안 게이트웨이, 라즈베리파이, 영상 마스킹, 객체 탐지, 프라이버시 보호

1. 서론
1.1 연구 배경
최근 가정용 IP 카메라, 월패드, 홈 IoT 장비의 보급이 증가하면서 개인 주거공간 내부의 영상 정보가 네트워크를 통해 실시간으로 송수신되는 환경이 일반화되고 있다. 그러나 IP 카메라는 인터넷에 연결된 영상 장비라는 특성상 해킹, 계정 탈취, 취약한 펌웨어, 비인가 접속 등의 보안 위협에 노출될 수 있다.
특히 가정 내부 영상은 거주자의 얼굴, 생활 패턴, 신체 정보, 사생활 공간 등 매우 민감한 정보를 포함하므로, 영상 유출이 발생할 경우 단순한 개인정보 침해를 넘어 심각한 사생활 침해로 이어질 수 있다. 기존의 IP 카메라 보안은 주로 제조사의 클라우드 서버, 공식 앱, 계정 인증 방식에 의존하는 경우가 많다. 하지만 제조사의 보안 수준이 충분하지 않거나 기기 자체에 보안 취약점이 존재하는 경우 사용자는 이를 직접 통제하기 어렵다는 한계가 있다.
1.2 연구 필요성
일반적인 IP 카메라는 외부 서버 또는 제조사 클라우드와 직접 통신하는 구조를 가진다. 이 구조에서는 사용자가 카메라의 네트워크 흐름을 완전히 통제하기 어렵고, 외부 서버 침해나 계정 탈취가 발생할 경우 원본 영상이 그대로 노출될 위험이 있다.
따라서 본 연구에서는 IP 카메라가 외부 인터넷과 직접 통신하지 않도록 망을 분리하고, 모든 영상 스트림을 라즈베리파이 기반 보안 게이트웨이를 통해 제어하는 구조를 제안한다. 또한 비인가 사용자가 영상에 접근하더라도 원본 영상이 아닌 마스킹 처리된 영상만 제공되도록 하여 영상 유출 피해를 최소화하고자 한다.
1.3 연구 목적
본 연구의 목적은 다음과 같다.
첫째, IP 카메라의 외부 직접 통신을 차단하고 라즈베리파이 기반 보안 게이트웨이를 통해 로컬 영상 스트림을 제어하는 구조를 설계한다.
둘째, 인가 기기와 비인가 기기를 구분하여 원본 영상과 마스킹 영상을 분기 제공하는 투트랙 접속 로직을 구현한다.
셋째, 객체 탐지 및 영상 처리 기술을 활용하여 비인가 접속 상황에서 민감 영역을 자동으로 마스킹하는 영상 처리 파이프라인을 구현한다.
넷째, 마스킹 처리율, 누출률, 프레임 기준 성공률, 과잉 마스킹률 등의 지표를 활용하여 제안 시스템의 성능을 평가한다.
1.4 연구 범위
본 연구는 가정용 IP 카메라 환경을 가정하여 라즈베리파이 기반 보안 게이트웨이 구조를 설계하고, 영상 스트림에 대한 마스킹 처리 및 성능 평가를 수행한다. 연구 범위는 다음과 같다.
•	IP 카메라와 라즈베리파이를 활용한 로컬 네트워크 구조 설계
•	IP 카메라의 외부망 통신 차단 및 로컬 스트림 확보
•	인가 기기와 비인가 기기 구분을 위한 접속 로직 설계
•	비인가 접속 시 객체 탐지 기반 영상 마스킹 처리
•	마스킹 처리 결과에 대한 정량적 성능 평가
단, 본 연구는 실제 공격자의 불법 침입 행위를 수행하는 것이 아니라, 보안 게이트웨이 구조와 비식별화 영상 처리 기능을 중심으로 방어적 관점에서 시스템을 구현하고 평가한다.

2. 관련 연구 및 이론적 배경
2.1 IP 카메라 보안 위협
IP 카메라는 네트워크를 통해 영상을 송수신하는 IoT 장비로, 일반적인 웹캠이나 폐쇄회로 CCTV와 달리 외부 접속 기능을 제공한다. 이러한 편의성은 원격 모니터링 측면에서는 장점이지만, 동시에 인증 우회, 취약한 비밀번호, 펌웨어 취약점, 암호화되지 않은 통신, 클라우드 서버 침해 등 다양한 보안 위협을 발생시킬 수 있다.
가정용 IP 카메라의 경우 사용자가 보안 설정을 직접 세밀하게 관리하기 어렵고, 제조사의 앱과 클라우드 서버에 의존하는 구조가 많다. 따라서 기기 자체의 보안성뿐만 아니라 네트워크 구조와 영상 접근 제어 방식까지 함께 고려해야 한다.
2.2 IoT 보안 게이트웨이
IoT 보안 게이트웨이는 IoT 기기와 외부 네트워크 사이에서 트래픽을 제어하고, 인증, 필터링, 암호화, 접근 제어 등의 기능을 수행하는 중간 장치이다. 보안 게이트웨이를 활용하면 개별 IoT 기기의 보안성이 부족하더라도 네트워크 단에서 추가적인 보호 계층을 구성할 수 있다.
본 연구에서는 라즈베리파이를 보안 게이트웨이로 사용하여 IP 카메라가 외부 인터넷과 직접 통신하지 못하도록 제한하고, 영상 스트림을 로컬 환경에서 수신 및 처리하는 구조를 설계한다.
2.3 영상 비식별화와 마스킹 처리
영상 비식별화는 영상 속 개인을 식별할 수 있는 얼굴, 신체, 사적 공간, 민감 객체 등을 흐림 처리, 모자이크 처리, 블러 처리, 영역 제거 등의 방식으로 보호하는 기술이다. IP 카메라 영상에서는 사람이 포함된 영역이 중요한 보호 대상이 될 수 있으며, 객체 탐지 모델을 활용하면 영상 속 인물 영역을 자동으로 탐지하고 해당 영역에 마스킹 처리를 적용할 수 있다.
본 연구에서는 비인가 접속 상황에서 원본 영상 대신 마스킹 영상만 제공되도록 하여, 해커가 계정 정보나 접속 경로를 일부 확보하더라도 원본 사생활 영상이 직접 유출되지 않도록 하는 것을 목표로 한다.
2.4 객체 탐지 기반 영상 처리
객체 탐지 기반 영상 처리는 영상 프레임에서 특정 객체의 위치를 탐지한 뒤, 해당 영역에 후처리를 적용하는 방식이다. 본 연구에서는 사람 영역을 탐지하고 해당 영역에 블러 또는 모자이크 처리를 적용하는 방식으로 민감 정보를 보호한다.
영상 처리 과정은 일반적으로 다음과 같이 구성된다.
1.	원본 영상 입력
2.	프레임 단위 분리
3.	객체 탐지 모델 적용
4.	탐지 영역 좌표 또는 마스크 추출
5.	탐지 영역 확장
6.	블러 또는 모자이크 처리
7.	마스킹 영상 출력
8.	정답 영역과 비교하여 성능 평가

3. 연구 방법
3.1 전체 시스템 구성
본 연구에서 제안하는 시스템은 IP 카메라, 라즈베리파이, 사용자 접속 기기, 웹 대시보드, 영상 처리 모듈로 구성된다. IP 카메라는 라즈베리파이에서 구성한 로컬 네트워크에 연결되며, 외부 인터넷과의 직접 통신은 차단된다. 사용자는 라즈베리파이 보안 게이트웨이를 통해서만 영상에 접근할 수 있다.
전체 시스템 구조는 다음과 같다.
•	IP 카메라: 실시간 영상 스트림 생성
•	라즈베리파이: 보안 게이트웨이 역할 수행
•	방화벽 설정: 외부 인터넷 직접 통신 차단
•	영상 처리 모듈: 비인가 접속 시 마스킹 처리 수행
•	접속 제어 모듈: 인가 기기와 비인가 기기 구분
•	웹 대시보드: 사용자 영상 확인 인터페이스 제공
3.2 망 격리 구조 설계
본 연구에서는 IP 카메라가 외부 클라우드 서버와 직접 통신하지 못하도록 라즈베리파이를 중심으로 로컬 네트워크를 구성한다. 라즈베리파이는 무선 AP 또는 중간 게이트웨이 역할을 수행하며, IP 카메라의 트래픽은 라즈베리파이를 통해서만 전달된다.
망 격리 구조의 핵심은 다음과 같다.
•	IP 카메라를 라즈베리파이 내부망에 연결
•	외부망으로 향하는 IP 카메라 트래픽 차단
•	라즈베리파이에서 로컬 영상 스트림 수신
•	사용자 접속은 라즈베리파이 웹 대시보드를 통해서만 허용
이를 통해 제조사 클라우드 서버에 대한 의존도를 낮추고, 사용자가 직접 통제 가능한 로컬 보안 구조를 구성한다.
3.3 투트랙 접속 로직
본 연구에서는 접속 기기의 인가 여부에 따라 서로 다른 영상 스트림을 제공하는 투트랙 접속 로직을 설계한다.
인가 기기가 접속한 경우에는 사용자 본인의 기기라고 판단하여 원본 영상을 제공한다. 반면, 비인가 기기 또는 신뢰할 수 없는 접속 환경에서는 원본 영상을 제공하지 않고 마스킹 처리된 영상만 제공한다.
투트랙 접속 구조는 다음과 같다.
•	인가 기기 접속: 원본 영상 제공
•	비인가 기기 접속: 마스킹 영상 제공
•	인증 정보가 불완전하거나 기기 식별이 불가능한 경우: 마스킹 영상 제공
•	관리자 설정에 따라 원본 영상 접근 권한 제한 가능
이 방식은 공격자가 계정 정보 일부를 획득하더라도 원본 영상 접근을 제한할 수 있다는 장점이 있다.
3.4 영상 마스킹 처리 방법
영상 마스킹 처리는 입력 영상에서 사람 또는 민감 객체 영역을 탐지한 뒤, 해당 영역에 블러 또는 모자이크 처리를 적용하는 방식으로 수행한다.
처리 절차는 다음과 같다.
1.	원본 영상 파일 또는 실시간 스트림 입력
2.	프레임 단위로 영상 분리
3.	객체 탐지 모델을 이용하여 사람 영역 탐지
4.	탐지된 영역을 바운딩 박스 또는 세그멘테이션 마스크로 변환
5.	탐지 영역을 일정 비율로 확장
6.	확장된 영역 전체에 블러 또는 모자이크 적용
7.	마스킹 처리된 프레임 저장
8.	전체 프레임을 결합하여 출력 영상 생성
3.5 성능 평가 방법
본 연구에서는 마스킹 처리 결과를 정량적으로 평가하기 위해 원본 영상, 마스킹 영상, 정답 바운딩 박스 정보를 비교한다. 정답 바운딩 박스는 보호되어야 할 대상 영역을 의미하며, 마스킹 영상에서 실제로 변화가 발생한 영역과 비교하여 마스킹 처리율을 산출한다.
주요 평가 지표는 다음과 같다.
3.5.1 마스킹 처리율
마스킹 처리율은 보호 대상 영역 중 실제로 마스킹 처리된 픽셀의 비율을 의미한다.
마스킹 처리율 = 실제 마스킹된 보호 대상 픽셀 수 / 전체 보호 대상 픽셀 수 × 100
3.5.2 누출률
누출률은 보호 대상 영역 중 마스킹되지 않고 남아 있는 픽셀의 비율을 의미한다.
누출률 = 100 - 마스킹 처리율
3.5.3 프레임 기준 성공률
프레임 기준 성공률은 각 프레임에서 마스킹 처리율이 기준값 이상인 경우를 성공으로 판단하고, 전체 평가 프레임 중 성공한 프레임의 비율을 계산한 값이다.
프레임 기준 성공률 = 성공 프레임 수 / 전체 평가 프레임 수 × 100
3.5.4 과잉 마스킹률
과잉 마스킹률은 보호 대상이 아닌 영역이 불필요하게 마스킹된 정도를 의미한다. 과잉 마스킹률이 지나치게 높으면 영상의 사용성이 저하될 수 있으므로, 보안성과 사용성의 균형을 함께 고려해야 한다.

라즈베리파이는 IP 카메라와 사용자 접속 기기 사이에서 중간 게이트웨이 역할을 수행한다. IP 카메라는 라즈베리파이 내부망에 연결되며, 라즈베리파이는 방화벽 설정을 통해 IP 카메라의 외부 인터넷 직접 접속을 제한한다.
게이트웨이 구현의 주요 기능은 다음과 같다.
•	IP 카메라 로컬 네트워크 연결
•	외부망 트래픽 차단
•	영상 스트림 수신
•	접속 기기 판별
•	원본 영상 또는 마스킹 영상 분기 제공
4.3 영상 처리 모듈 구현
영상 처리 모듈은 OpenCV를 활용하여 입력 영상을 프레임 단위로 처리한다. 객체 탐지 모델을 통해 사람 영역을 탐지하고, 탐지된 영역에 블러 처리를 적용한다. 처리된 프레임은 다시 영상 파일로 저장되며, 필요 시 웹 대시보드에서 실시간으로 출력할 수 있다.
영상 처리 모듈의 핵심 기능은 다음과 같다.
•	원본 영상 불러오기
•	프레임별 객체 탐지
•	보호 대상 영역 추출
•	탐지 영역 확장
•	블러 또는 모자이크 적용
•	결과 영상 저장
4.4 성능 평가 모듈 구현
성능 평가 모듈은 원본 영상과 마스킹 영상의 차이를 비교하여 실제로 마스킹이 적용된 영역을 계산한다. 이후 정답 바운딩 박스와 비교하여 마스킹 처리율, 프레임 기준 성공률, 누출률 등을 산출한다.
평가 결과는 CSV와 JSON 파일로 저장하여 이후 분석 및 보고서 작성에 활용한다.

6.2 평가 결과 분석
실험 결과, 마스킹 처리율이 높을수록 보호 대상 영역이 효과적으로 비식별화되었음을 의미한다. 반대로 누출률이 높게 나타날 경우, 객체 탐지 실패, 마스크 영역 부족, 프레임 간 객체 이동, 낮은 해상도, 조명 변화 등의 요인이 영향을 미쳤을 가능성이 있다.

6.3 문제점 및 개선 방향
실험 과정에서 발생할 수 있는 주요 문제점은 다음과 같다.
첫째, 객체 탐지 모델이 일부 프레임에서 사람 영역을 정확하게 탐지하지 못할 경우 마스킹 누락이 발생할 수 있다.
둘째, 세그멘테이션 마스크가 실제 사람 영역보다 작게 생성될 경우 보호 대상 일부가 노출될 수 있다.
셋째, 프레임 간 객체 이동이 빠른 경우 이전 프레임의 마스크를 재사용하는 방식에서 위치 오차가 발생할 수 있다.
넷째, 라즈베리파이의 연산 성능 한계로 인해 실시간 처리 속도가 저하될 수 있다.
이를 개선하기 위해 본 연구에서는 바운딩 박스 전체 마스킹, 마스크 확장 비율 조정, 탐지 주기 최적화, 경량 모델 적용, 해상도 조정 등의 방법을 검토한다.

7. 논의
본 연구는 IP 카메라 보안 문제를 단순히 계정 관리나 비밀번호 변경의 문제로 보지 않고, 네트워크 구조와 영상 비식별화 처리를 결합하여 해결하고자 하였다는 점에서 의의가 있다. 특히 보안 게이트웨이를 통해 IP 카메라의 외부 직접 통신을 차단하고, 비인가 접속 시 마스킹 영상만 제공하는 구조는 원본 영상 유출 가능성을 줄이는 데 기여할 수 있다.
다만 본 연구는 프로토타입 수준의 구현이므로 실제 가정 환경에서 장기간 안정적으로 동작하는지에 대한 추가 검증이 필요하다. 또한 객체 탐지 기반 마스킹은 탐지 모델의 성능에 따라 결과가 달라질 수 있으므로, 다양한 영상 환경과 조명 조건, 사람의 자세, 거리, 움직임에 대한 추가 실험이 요구된다.

8. 결론
본 연구에서는 가정용 IP 카메라 영상 유출 문제를 해결하기 위해 라즈베리파이 기반 보안 게이트웨이 구조와 객체 탐지 기반 영상 마스킹 방식을 제안하였다. 제안 시스템은 IP 카메라의 외부 직접 통신을 차단하고, 사용자가 제어 가능한 로컬 게이트웨이를 통해 영상 스트림을 관리하도록 설계되었다. 또한 인가 기기와 비인가 기기를 구분하여 비인가 접속 시 원본 영상이 아닌 마스킹 영상만 제공함으로써 영상 유출 피해를 줄이고자 하였다.
실험에서는 원본 영상과 마스킹 영상, 정답 바운딩 박스를 비교하여 마스킹 처리율과 누출률을 평가하였다. 이를 통해 제안한 영상 처리 방식의 보호 성능을 정량적으로 확인할 수 있었다. 향후 연구에서는 라즈베리파이 환경에서의 실시간 처리 성능을 개선하고, 다양한 IP 카메라 및 실제 가정 환경에서의 적용 가능성을 검증할 필요가 있다.
